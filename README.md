# Bookmarks: a 3-service app in the cloud

A small bookmarks app, built to practice deployment: the code is deliberately tiny.

```
 browser
    │
    ▼
 web   Leptos (Rust → WebAssembly)   Azure Blob Storage, static website
    │  HTTPS
    ▼
 api   Axum (Rust), in a container   Azure Container Apps
    │  TLS, DB_URL from a Container App secret
    ▼
 db    PostgreSQL 16                 Azure Database for PostgreSQL (flexible server)
```

| Folder | What it is |
|---|---|
| `api/` | The REST API (`axum` + `sqlx`) and its `Dockerfile` (multi-stage, distroless, non-root) |
| `web/` | The frontend, one page built with `leptos` and `trunk` |
| `infra/terraform/` | The managed resource: the PostgreSQL server, its database and firewall rule |
| `.github/workflows/api.yml` | CI/CD: build, push the image, deploy |
| `compose.yaml` | The API plus a local Postgres, for development |

## The API

| Endpoint | Does |
|---|---|
| `GET /api/bookmarks` | List all bookmarks, newest first |
| `POST /api/bookmarks` | Add one: `{"title": "...", "url": "..."}` |
| `PUT /api/bookmarks/{id}` | Change one |
| `DELETE /api/bookmarks/{id}` | Remove one |
| `GET /health` | Returns `ok` |

Configuration comes from environment variables only:

| Variable | Meaning |
|---|---|
| `DB_URL` | Postgres connection string, required. It holds the password, so it is never in the code. |
| `PORT` | Port to listen on (default `8080`) |

## Run it locally

```bash
docker compose up --build          # API on http://localhost:8090, with its own Postgres
cd web && trunk serve              # frontend on http://localhost:8080, talks to the API above
docker compose down -v             # stop and delete the data
```

## Deploy

1. **Database** (Terraform). The password is generated by Terraform; the state file holds it and is not committed.
   ```bash
   cd infra/terraform
   cp terraform.tfvars.example terraform.tfvars      # put your subscription id in it
   terraform init && terraform plan && terraform apply
   ```
2. **API image**: built for `linux/amd64` and pushed to Docker Hub (done by the pipeline, below).
3. **API** on Container Apps: external ingress on port `8080`, and `DB_URL` stored as a **secret**
   (`--secrets db-url=... --env-vars DB_URL=secretref:db-url`).
4. **Frontend**: the API address is fixed when the page is built, then the files go to the `$web` container.
   ```bash
   cd web && API_URL=https://<your-api-url> trunk build --release
   az storage blob upload-batch --account-name <storage> -d '$web' -s dist --overwrite
   ```
   The `.wasm` file must be served as `application/wasm`.

## CI/CD (GitHub Actions)

- **Pull request:** the image is built, nothing is published.
- **Push to `main`:** the image is built and pushed to Docker Hub as `flaviusfen/bookmarks-api:<commit sha>`, then
  the Container App is updated to that exact tag. Every deploy traces back to its commit, and a rollback is
  deploying an older tag.
- **No Azure password is stored.** The job logs in with OIDC: GitHub gives it a signed token, and an Azure managed
  identity trusts only this repository's `main` branch. That identity is a Contributor on one resource group only.
- The only stored secret is the Docker Hub token (`DOCKERHUB_TOKEN`).

## Choices and things I hit

- **Region.** The student subscription allows only a few regions. Azure refused the `B1ms` server in France Central
  (`SkuNotAvailable`), although the region lists it; Poland Central accepted it.
- **Image architecture.** Building Rust for `amd64` on an Apple Silicon laptop is slow under emulation, so the
  pipeline builds it on an `amd64` runner.
- **Cost.** The database is the only resource that costs real credit (about 0.02 USD per hour for `B1ms`).
  Everything is deleted after use: `terraform destroy`, then `az group delete -n rg-seminar`.

## What I would change for real production

- Put the database in a private network instead of a public endpoint with a firewall rule, and keep the secret in
  Key Vault.
- Run at least two replicas with a `/readyz` probe, and use a canary release instead of replacing the app at once.
- Add logs, metrics and alerts (OpenTelemetry), a remote and locked Terraform state, and a staging environment.
- Add input validation and a database migration tool; the API creates its table at startup, which is fine here
  but not for a team.
